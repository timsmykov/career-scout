# Публичная alpha: проверка поставки

**0.1.0 alpha · MIT.** Этот документ описывает обезличивание относительно исходной
личной установки. Стабильность1.x и широкая смысловая точность не заявляются.
[Настройка своего экземпляра](personalization.md).

## Граница между кодом и личной установкой

В Git публикуются runtime, схемы, нейтральный TOML, вымышленные примеры, тесты,
документация и история разработки. Резюме кандидата, env/ключи, OAuth/ChatGPT login,
рабочие SQLite, model receipts и история откликов остаются вне репозитория.
Авторство и история разработки сохранены; переписывание истории не выполнялось.
Датированные исследования и примеры прежних профессий описывают развитие проекта,
а не конфигурацию нового пользователя.

## Что обезличено

- В стандартном поиске нет Product/BA/assistant/automation, IT/финтеха, города,
  ограничения junior/middle и потолка3года.
- Перед сетевым сбором требуются свои запросы; placeholder не отправляется на API.
- Разрешение хранения SuperJob не наследуется: default false, собственное решение
  задаётся в плане/TOML.
- Decisions не зависит от OpenBot volume/имени сервера; binary и корень задаёт пользователь.
- Экспорт не содержит конкретный agent UUID и не выполняет chown на UID1000.
- AGENTS описывает переносимый проект; приватные рабочие инструкции сохранены
  в прежней серверной рабочей копии.
- Основная инструкция установки и ссылки относятся к main, не к личной development-ветке.

## Проверка истории и приватности

До открытия репозитория выполнены gitleaks по всем доступным refs и точное
сравнение639существовавших Git blobs с4credential-значениями из приватного env.
Совпадений с этими credentials нет. Восемь срабатываний gitleaks проверены как
64-символьные evaluation_key в вымышленных JSON, не credentials. Эта проверка не
является доказательством отсутствия любого возможного секрета; реальные private
каталоги и credentials дополнительно исключены правилами Git/упаковки.

Новые изменения проходят повторный скан. check_public_distribution в CI проверяет
нейтральный конфиг, явный коннектор, пустые credential-примеры и отсутствие tracked
private/data/resumes/credentials/secret файлов. Он не читает реальные ключи и
не отправляет их внешнему сканеру. Персональная серверная установка не обновляется
автоматически при публикации кода; её конфиги, данные и контейнеры сохраняются.

## Техническая приёмка

- 489offline-тестов: прежнее ядро и новые сценарии нейтральной установки.
- Нестандартная профессия/senior/12лет без скрытого отказа из-за автора.
- Отказ от placeholder-запроса до сети/credentials/БД.
- Экспорт только в явно заданный каталог,0600, текущий владелец и запрет перезаписи.
- Схемы соответствуют runtime-моделям; JSON-примеры, ссылки, Ruff, wheel/sdist.
- Отдельный Docker image и тестовые volumes для persistence/полного установленного пути.
- После публикации проверяются main, анонимный доступ и клонирование без credentials.

Проверки не вызывают реальные модели и job API. Исходный [аудит0.1](product-audit-0.1.md)
остаётся отдельным историческим протоколом; его484теста не являются неизменным
числом тестов всех последующих коммитов.

## Пределы полезности

Один CV — самый простой самостоятельный путь. Несколько CV требуют внешнего
Decisions-коннектора; он пока не включён в пакет. Модель Codex и её доступность
пользователь выбирает для своей подписки. Архитектура допускает разные профессии,
но хорошие запросы, условия и контроль качества требуют настройки кандидата.
