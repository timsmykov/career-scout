# Приёмка технического ядра

Этот контракт определяет проверяемую готовность модулей, а не обещание неизменности
внешних API или безошибочной семантической оценки. Все предметные критерии и текущая
выдача остаются прежними. История откликов не перерабатывается.

## Источники и данные

- Все четыре адаптера различают корректную выдачу и изменение обязательного
  формата/типа. Ошибки декодирования и обязательных структур дают безопасный код,
  не пустой успешный результат. Дополнительные поля источника допускаются.
- В странице обязательны непустые строковые source ID. Ошибочная страница не
  продвигает cursor. Уже сохранённые карточки не удаляются.
- JSON с повторёнными ключами, NaN/Infinity и числовым переполнением отвергается
  на границе чтения HTTP. Воркеры и квитанции Decisions также читаются строго.
- `probe` выполняет ограниченные поиск и detail без открытия базы; дополнительно
  возвращает безопасный отчёт качества и подпись наблюдаемой структуры источника.
  Подпись служит диагностикой: отличие двух разных карточек не доказывает поломку
  API. Контрактные тесты отдельно различают допустимые дополнения и нарушения.

`data_quality.salary_facts` — общая проекция, не фильтр кандидата. Она сохраняет
исходные суммы и различает отсутствие, частичную известность и противоречие.
Ноль не становится пропуском; обратные границы не переставляются. Частота выплат
не умножает ставку. Для явно годовой ставки месячный эквивалент делится на12;
для часовой/дневной/сменной ставки без объёма работы эквивалент неизвестен.
Без явного периода месячная сумма не выдумывается. Валюта и gross/net сохраняются,
налоги и валюты автоматически не конвертируются. Расчётные значения возвращаются
отдельно десятичными строками, существующие snapshots и hashes не меняются.

## Ответы и доказательства

Корректная оболочка батча содержит `results`; посторонние evaluation_key дают
техническую ошибку. Пропуск/повтор конкретного ожидаемого элемента остаётся
ошибкой элемента, успешные соседи сохраняются. Ссылки на доказательства должны
содержать строковые from/to, принадлежать выбранному исходнику и непрерывному
диапазону. Схемы входов и результатов допускают безопасные строковые идентификаторы
резюме/очереди вместо enum профессий; для прежних данных поле называется profile_id.

Наличие корректной цитаты не доказывает правильность её семантической интерпретации.
Тюнинг Decisions/LLM и метрики качества являются отдельной работой.

## Очередь

Набор очередей берётся из сохранённого order; число слотов задаётся независимо
через routing.workers (1–4, по умолчанию4). Один батч по-прежнему содержит одно
резюме и до20полных вакансий. Рабочая конфигурация владельца не меняется.

Проверяется обработка1/2/7подготовленных резюме, соблюдение лимита пула, отсутствие
повтора готовых evaluation_key и завершение журнала попыток после ошибки воркера.
Неожиданное исключение воркера становится worker_execution_error и останавливает
новую выдачу; оно не считается отказом кандидату. Неправильный результат одного
элемента не затирает корректного соседа. Неизвестный исход не разрешает скрытый
повтор обращения.

Это готовность ядра очереди. Полный подготовительный CLI и текущий Decisions-router
пока сохраняют прежнюю конфигурацию четырёх направлений. Они не объявляются
универсальными только потому, что очередь умеет принимать другие идентификаторы.

## Переносимые подключения

`model.executable` задаёт путь к установленному Codex CLI. Отсутствующее/null значение
сохраняет прежний model_config_hash, значение по умолчанию — codex. Явное изменение
исполнителя меняет ключ модели. Вызов остаётся списком аргументов, не shell-строкой;
текущая ChatGPT авторизация не читается и не копируется.

`routing.native_binary` и `routing.workspace_root` задают подключение с существующим
контрактом `decisions --request-file ... --output ...`. По умолчанию сохраняются
нынешний native connector и его ограниченный OpenBot root. Явный root нужен для
иной личной установки; он не расширяет разрешения самого внешнего коннектора.
Workspace должен существовать внутри root. Ключи не передаются как аргументы.

Один и тот же body защищён файловым flock по хэшу для отдельных клиентов и процессов.
Повтор читает сохранённую квитанцию; неизвестная/невалидная квитанция не становится
разрешением повторить платный запрос. Проверки выполняются на синтетическом
коннекторе вне OpenBot, реальные настройки провайдеров не меняются.
Начало каждой внешней попытки отмечается до вызова: таймаут без квитанции остаётся
неизвестным исходом и после перезапуска клиента. Старый request без отметок попыток
при отсутствующей квитанции требует сверки; валидные старые квитанции читаются.

## Доказательства

Основная приёмка: tests/test_core_contracts.py. Существующие проверки источников,
нормализации, миграций, очередей и controlled retry остаются обязательными.
Общий CI не получает секретов и не обращается к моделям/площадкам. Ограниченный
живой probe — отдельное свидетельство, а не гарантия будущей доступности API.
