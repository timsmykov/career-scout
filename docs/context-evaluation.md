# Персональная оценка по контексту

Новый путь: **контекст → план/сбор → admission → явные условия → Decisions →
очереди резюме → Codex → проверка доказательств → подборка**. Профессии не зашиты
в код: используются resume_id и полные исходники из контекста. Прежние анализы
applications-1 и их постоянные исключения остаются отдельным совместимым режимом.

## Граница кода и моделей

| Шаг | Исполнитель | Контракт |
|---|---|---|
| Настройка | Вызывающий агент и CLI | Агент читает цели/резюме и задаёт запросы; код проверяет входы и версии |
| Сбор и хранение | Код | Площадки, страницы, окно, сохранённые ID, исходники, продолжение |
| Структурированные ограничения | Код | Только явно заданные fact_rules и известные факты; неизвестное сохраняется |
| Выбор резюме | Native Decisions | Динамические choices из резюме; один/два профиля по близости вероятностей |
| Оценка соответствия | Codex через подписку | Основная работа, переносимый опыт, обязательность, пожелания, неопределённость |
| Проверки и выдача | Код | Цитаты, полный охват пожеланий, допустимость вывода, история, категории и порядок |

Свободный текст не компилируется в regex или список профессий. Он передаётся
моделям целиком вместе с приоритетами. Агент может дополнительно записать явное
fact_rule; программа не придумывает из пожелания новую обязательную квалификацию.
Атрибуты задают условия поиска и не доказывают навыки, отсутствующие в резюме.

## Подключения и проверка установки

```sh
career-scout --workspace private/me connection put default \
  --input examples/agent-connection.synthetic.json --request-id connection-1
career-scout --workspace private/me connection show default
career-scout --workspace private/me doctor --connection default --env /absolute/path/jobs.env
```

[Пример подключения](../examples/agent-connection.synthetic.json) выключает внешние
вызовы. В рабочем файле можно явно включить external_calls_enabled. Модель оценщика,
reasoning, executable, лимиты контекста/батча, число слотов и параметры маршрутизации
заменяемы. Для Decisions задаётся `decisions:{binary,workspace,workspace_root}`.
Binary должен реализовывать `decisions --request-file PATH --output PATH` по
существующему контракту DecisionsClient. Native wrapper использует собственную
авторизацию; ключи в CLI не передаются и не копируются. Исполнитель задаётся явно и не входит в поставку. По умолчанию используется
имя career-scout-decisions в PATH; настройте свой совместимый коннектор.

Doctor проверяет наличие исполняемых файлов, разрешённый каталог native-работы,
доступность workspace и credential-файла. Возвращает конкретные next-компоненты,
не делает сетевых вызовов и не выдаёт наличие файла за действующую авторизацию:
`auth_live_verified=false`. Работоспособность авторизации проверяется ограниченным
живым запуском отдельно. Поддерживаются личные каталоги данных; общего сервера нет.

## Подготовка и выполнение

```sh
# Готовые полные карточки из сохранённого запуска коллектора:
career-scout --workspace private/me evaluation prepare --context CONTEXT_ID \
  --collection-run COLLECTION_RUN_ID --connection default --limit 100 \
  --max-calls 10 --max-decisions 100 --request-id prepare-1
# Или явный JSON snapshot: массив vacancy-v2 / объект {vacancies:[...]}:
career-scout --workspace private/me evaluation prepare --context CONTEXT_ID \
  --catalog private/vacancies.json --limit 100 \
  --max-calls 10 --max-decisions 100 --request-id prepare-2
career-scout --workspace private/me evaluation run RUN_ID --db DATABASE --request-id run-1
career-scout evaluation status RUN_ID --db DATABASE
career-scout --workspace private/me evaluation resume RUN_ID --db DATABASE \
  --additional-calls 2 --additional-decisions 20 --request-id resume-1
```

Prepare не вызывает модели. Если запуск подготовлен с external_calls_enabled=false,
его можно явно активировать `evaluation run/resume ... --enable-calls` с новым
request-id. Меняется только разрешение выполнения этого run; контекст, модель,
входы и конечные бюджеты сохраняются, новые карточки не принимаются повторно.
Без этого флага разрешение не повышается. Профиль подключения для будущих запусков
сам по себе не меняется.

Prepare не вызывает модели. Закрепляются контекст, версия, полный текст карточек,
параметры подключения и отдельные бюджеты Decisions/Codex. БД анализа находится в
`WORKSPACE/evaluations/CONTEXT_ID/CONTEXT_HASH.sqlite3`. Файловый lock сериализует
подготовку и выполнение. Записывающие evaluation-команды отказываются работать
с БД вне этого каталога. Исходный collector и прежняя рабочая БД не изменяются.

Каждый source/source_id принимается в этом контексте только один раз, включая
отклонённые и незавершённые карточки. Следующий prepare выбирает следующий остаток.
Resume завершает старый run, не создаёт новую порцию. Изменение контекста создаёт
отдельный набор оценок; прежние решения остаются историей, но не притворяются
оценкой по новым пожеланиям. История откликов общая для личного workspace.

Для одного резюме классификация не нужна: оно назначается кодом, если не включён
Decisions-отсев. При нескольких резюме Decisions получает весь контекст и полную
карточку. Choices — resume_id плюс служебные uncertain/mismatch. Если два лучших
резюме близки (по умолчанию gap≤0.10), оцениваются оба, включая случай, когда один
уже дал PASS. Доминирующий uncertain/mismatch при выключенном отсеве также идёт
оценщикам. Отказ выбранных оценщиков не означает отказ всех остальных резюме.

`allow_decisions_exclusion` по умолчанию false: для нового человека ещё нет
подтверждённой калибровки ложного отсева. При явном включении mismatch исключает
карточку начиная с exclusion_threshold (по умолчанию0.995). Само число вероятности
не доказывает точность. Такой режим следует проверять на отложенной разметке.

Слотов1..4, батч1..20 и одно резюме на вызов. Независимо от размера батча
проверяется лимит контекста; слишком большой вход не обрезается. Все технические
ошибки видны отдельно, не считаются отказом кандидату. Уже маршрутизированные
карточки могут завершить LLM-оценку при исчерпании бюджета дальнейшего Decisions.

`--retry-errors` явно открывает новую конечную попытку для технически невалидных
ответов, готовые evaluation_key не повторяются. Это не сброс бюджета. Незавершённая
попытка или неизвестная ошибка воркера блокируют повтор до сверки; новый request-id
и retry-errors не обходят эту защиту. Исходные ответы и цитаты не переписываются.

## Явные ограничения кодом

Контекст принимает fact_rules с id, field, operator, value и guards. Поддержаны
операторы eq/in/not_in/gte/lte и пути в полной vacancy-v2. Нет eval или shell.
Например, заведомо низкая верхняя месячная зарплата в рублях:

```json
{
  "id": "salary_floor",
  "field": "attributes.salary.amount_to",
  "operator": "gte",
  "value": 80000,
  "guards": {
    "attributes.salary.currency": "RUB",
    "attributes.salary.period": "month"
  }
}
```

Отсутствующая зарплата, другая валюта, неизвестный период, конфликт нормализации
или несопоставимый тип дают unknown, а не отказ. Для денежных правил currency и
period обязательны. Gross/net автоматически не пересчитываются; при требовании
net нужно явно добавить guard `attributes.salary.gross:false`. Часовые/годовые
цифры не сравниваются с месячным порогом. Текстовые сложные условия вроде «офис
только в Москве, удалённо откуда угодно» можно оставить модели свободным пожеланием.

## Решения и неопределённость

Сохранённый ContextResult v4 имеет PASS/UNCERTAIN/REJECT и questions=[].

- PASS: есть доказанная основа основной работы, нет существенного неразрешённого
  препятствия. Неизвестная зарплата или желательная библиотека могут остаться в
  uncertainties без автоматического отказа.
- UNCERTAIN: неясна основная пригодность или обязательное условие. Оценка завершена,
  это не техническая ошибка и не вопрос кандидату.
- REJECT: есть конкретное существенное основание: основная работа вне профиля,
  подтверждённый конфликт или доказанное нарушение обязательного пожелания.
  Отсутствие навыка в тексте само по себе не превращается в доказанный конфликт.

Для каждого пожелания проверяется ровно один preference_check met/violated/unknown.
У met/violated обязательна цитата вакансии; required/avoid с unknown не допускает
PASS. Preferred с unknown/violated не превращается в запрет. Проверяются также
источник и непрерывность цитат, ключ результата, одно резюме на батч и разделение
карточек. Корректная цитата не гарантирует правильной смысловой трактовки.

## Подборка, история и метрики

```sh
career-scout evaluation shortlist --db DATABASE --limit 20
career-scout evaluation shortlist --db DATABASE --include-uncertain
career-scout shortlist list --analysis-db DATABASE
career-scout explain --analysis-db DATABASE --source hh --id VACANCY_ID
career-scout --workspace private/me history import --input private/history.json --request-id import-1
career-scout --workspace private/me history list
career-scout evaluation metrics RUN_ID --db DATABASE
career-scout evaluation metrics RUN_ID --db DATABASE --labels private/labels.json
```

Стандартная выдача содержит PASS, категории — названия резюме. Отдельный флаг
добавляет UNCERTAIN с явной пометкой. Сначала идут PASS, затем неопределённые;
приоритет внутри — соблюдённые пожелания. Причины/допущения возвращаются вместе
со ссылкой и условиями. Explain читает также правила/Decisions до LLM. Учитывается
актуальность по freshness_days (по умолчанию14); публикация с неизвестной датой
сохраняется как неизвестная. Старые и недоступные карточки отмечаются до моделей.

История — массив объектов operation_id/source/source_id/kind/evidence/detail.
Переимпорт того же события безопасен; другой смысл с тем же ID даёт конфликт.
Applied/dismissed/withdrawn/rejected скрывают повторный отклик во всех версиях
контекста личной установки; reopened снимает блокировку. Никаких откликов или
действий на площадках импорт не выполняет. Реальная старая история автоматически
не переносится в новый workspace без явного импорта с происхождением.

Метрики показывают исходы, технические ошибки, неопределённость, зарезервированные
вызовы Decisions/Codex, батчи и измеренные tokens. Без контрольной разметки качество
обозначено measured=false. Разметка задаётся объектом context_hash и cases со
source/source_id/expected (PASS/UNCERTAIN/REJECT). Возвращаются confusion, precision,
recall, доля ложных отказов, accuracy, abstention и technical_error_rate **только
на предоставленной выборке**. Пустая, чужая или повторённая разметка отвергается.

Это реализованный механизм измерения. Рыночная точность для любого человека и
безопасный порог Decisions требуют репрезентативной независимой разметки; их
нельзя объявить100% по успешному CI или четырём вымышленным вакансиям.
