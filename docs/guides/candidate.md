# Настроить резюме и условия

Сначала пройдите [установку](../quickstart.md). Этот документ описывает новый
персональный контекст, а не конфиги старых четырёх профилей.

## Полный текст и произвольные профессии

В `private/context.json` сохраняются полные исходники. Пример вымышленный:

```json
{
  "resumes": [
    {"id": "integration", "title": "Специалист интеграций", "text": "Интегрировал API. Разрабатывал сервисы на Python."}
  ],
  "goals": "Разработка интеграций и внутренних сервисов",
  "preferences": [
    {"statement": "Удалённая работа или офис в Москве", "priority": "required"},
    {"statement": "Работа с небольшими продуктовыми командами", "priority": "preferred"}
  ]
}
```

Замените содержимое своим опытом. Допускается 1–100 резюме с уникальными ID;
названия профессий не enum. Атрибуты и цели не доказывают отсутствующие в CV навыки.
Модель получает полный текст выбранного резюме, а не общий пересказ биографии.

## Что обязательно, что желательно

| Приоритет | Как используется |
|---|---|
| required | Обязательное пожелание; unknown не допускает PASS |
| preferred | Предпочтение; неизвестное или несоблюдение само по себе не запрещает PASS |
| avoid | Условие, которого нужно избежать; violated/unknown не допускает PASS |

Пишите avoid однозначно, например «Избегать работы с обязательными ночными сменами».
Каждое пожелание сохраняется со своим preference_id. Модель должна вернуть его
проверку met/violated/unknown с обоснованием и требуемыми цитатами.
Неизвестная зарплата может оставаться второстепенной неопределённостью.

## Когда нужно явное правило

Свободное сложное условие можно передать модели. Детерминированное fact_rule
уместно, когда поле и способ сравнения однозначны. Пример исключает известную
верхнюю границу месячной рублёвой зарплаты ниже80тысяч:

```json
{
  "resumes": [{"id": "integration", "title": "Интеграции", "text": "Вымышленный полный исходник резюме."}],
  "fact_rules": [{
    "id": "salary_floor",
    "field": "attributes.salary.amount_to",
    "operator": "gte",
    "value": 80000,
    "guards": {"attributes.salary.currency": "RUB", "attributes.salary.period": "month"}
  }]
}
```

Отсутствующая сумма/верхняя граница, конфликт нормализации или неизвестный период
дают unknown, а не отказ. Налоги и валюта не пересчитываются. Если нужен порог net,
добавьте guard `attributes.salary.gross:false`; gross и net без него не разделяются.
[Операторы и ограничения](../context-evaluation.md).

## Создание и изменение

```sh
career-scout --workspace private/me context create   --input private/context.json --request-id candidate-1
career-scout --workspace private/me context show CONTEXT_ID --summary
career-scout --workspace private/me context show CONTEXT_ID --version 1
```

Изменение — JSON с заменяемыми полями верхнего уровня, например
`{"preferences":[{"statement":"Только удалённо","priority":"required"}]}`:

```sh
career-scout --workspace private/me context update CONTEXT_ID   --input private/patch.json --if-version 1 --request-id candidate-2
```

Массив заменяется целиком, скрытого merge нет. Конкурирующее обновление получает
version_conflict; перечитайте версию до повторного изменения. После обновления
создайте новый plan, иначе его запуск вернёт plan_context_stale. Старый запущенный
проход остаётся на своей версии. Оценки новой версии хранятся отдельно.

При нескольких CV настройте [Decisions-подключение](../context-evaluation.md).
Самый простой первый опыт — одно резюме с выключенным автоматическим отсевом.
