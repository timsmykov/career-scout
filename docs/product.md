# Задача и границы

Career Scout помогает человеку найти вакансии, на которые имеет смысл откликнуться.
Вместо повторного чтения выдачи нескольких площадок он получает сохранённый каталог
и подборку, сопоставленную с его резюме и условиями. Это личный CLI версии **0.1.0 alpha**.
[Первая подборка](quickstart.md) · [Проверенное состояние](product-audit-0.1.md).

## Входы и результат

Вход — полные тексты одного или нескольких резюме, цели, свободные пожелания,
явные ограничения, запросы к площадкам и конечные бюджеты. Произвольные профессии
и resume_id поддерживаются новым контекстом; скрытых IT/стажевых ограничений нет.

Выход — актуальная по настроенному окну подборка PASS: ссылка на оригинал,
категория резюме и основания. UNCERTAIN доступен отдельным флагом. Неопределённость
сохраняется без вопросов кандидату. Техническая ошибка или исчерпанный бюджет
не означают отказ по вакансии.

Оценка использует резюме и переданные условия. Контекст не дополняется выдуманным
опытом из чатов, общей памяти агента или соседнего резюме. Зарплата без суммы
не становится нулём; обязательный порог применяется только к сопоставимым фактам.

## Уже реализовано

- Read-only сбор полных вакансий из HH, Habr, SuperJob и «Работы России».
- Хранение исходников, версий, условий и прогресса; initial/new/resume без дублей ID.
- Версионированный персональный контекст и настраиваемый план для вызывающего агента.
- Выбор одного/двух резюме через внешний Decisions-коннектор; без него для одного CV.
- Codex через подписку: батчи одного резюме, проверка цитат, кэш, конечные бюджеты.
- Подборка, explain, импорт истории откликов и метрики по контрольной разметке.

[Ответственность компонентов](architecture.md). Доступ к API и хранению данных
должен быть разрешён отдельно для каждой установки. Habr использует frontend,
а не подтверждённый публичный search API.

## Границы первой версии

Приложение не отправляет отклики, не меняет резюме, не общается с работодателями
и не создаёт расписаний. Нет UI, общего multi-user сервера, HTTP API или MCP-сервера.
CSV, refresh старых полных описаний и общая retention-политика не заявлены.
Выдача ограничена настроенными запросами и доступной глубиной источников.

Личная alpha полезна при настроенном хостовом Codex. Самостоятельная установка
с несколькими CV ещё требует внешнего native Decisions helper. Качество смыслового
отбора требует широкой контрольной разметки; тесты не являются гарантией точности.

## Совместимость с первоначальным сценарием

Первый рабочий сценарий владельца включал Product, автоматизацию, бизнес-ассистента
и BA, технологические отрасли и отдельные ограничения. Он сохранён через старые
analysis-команды и приватные конфиги. Это не профессиональный enum продукта.

Старый first-PASS последовательно останавливается при принятии. Более поздний routed
режим назначает один/два профиля и завершает обе оценки. Новый context-1 использует
произвольные резюме и PASS/UNCERTAIN/REJECT. [Различия интерфейсов](agent-cli.md).
