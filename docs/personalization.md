# Настроить Career Scout под себя

Публичный пакет не содержит кандидатский профиль автора. Личная рабочая установка
с её резюме, условиями, доступами и историей находится вне Git. Имя автора и MIT
copyright — авторство кода, не обязательная идентичность пользователя.

## Минимальный путь без изменения кода

1. Установите main по [первому запуску](quickstart.md).
2. Выберите свой приватный --workspace и собственный env-файл площадок.
3. Передайте полные тексты резюме с произвольными resume_id через context create.
4. Добавьте цели и свои preferences с required/preferred/avoid. Неизвестное
   сохраняется; обязательные формализованные ограничения задаются fact_rules.
5. Составьте plan.queries под фактические задачи, а не под четыре старые профессии.
6. Выберите доступную модель через подписку или API, размер батча/число слотов и
   конечный бюджет. [Настройки исполнителя](model-providers.md).
7. Соберите карточки, передайте collection-run в evaluation и прочитайте shortlist.

Первый опыт — одно CV и выключенный Decisions-отсев. В этом режиме не нужен внешний
router или OpenBot: сбор и оценка работают через CLI и выбранное подключение модели.
Для нескольких CV подключите совместимый Decisions-коннектор явно. Он не включён
в поставку; отсутствие коннектора не должно маскироваться как отказ кандидату.

## Что именно настраивается

| Потребность | Поле/команда | Значение по умолчанию |
|---|---|---|
| Профессия и опыт | resumes[].text/id/title | Нужен ваш документ; публичные примеры вымышленные |
| Цели и условия | goals/preferences/fact_rules | Не выводятся из биографии автора |
| Зарплата | Явное fact_rule с guards валюты/периода/gross | Отсутствующая зарплата сохраняется; общего порога нет |
| География | area_ids и source_options конкретной площадки | Нет предустановленного города |
| Запросы/площадки | plan.queries/sources | Выбираете явно |
| Стаж и грейд | collection_policy либо свободные пожелания | Нейтральный план допускает все категории, без потолка лет |
| Исполнитель | connection.model, connection.decisions | По умолчанию Codex; можно выбрать Claude/API, Decisions задаётся отдельно |
| Объём и стоимость | HTTP/Decisions/модельные бюджеты, workers/batch_size | Конечные явные лимиты; бюджет вызовов не является денежным лимитом |
| Данные и история | --workspace | Отдельная личная установка |

Свободные условия не превращаются автоматически в regex или доказанный навык.
Для другой цели меняйте контекст/план, не редактируйте рубрики в исходниках.
[Контекст](guides/candidate.md), [сбор](guides/collection.md), [оценка](guides/evaluation.md).

## Прежний TOML и Docker

configs/search.toml нейтрален: все категории стажа/грейда, пустая отрасль,
max_required_years не задан, география не ограничена. Placeholder запроса требует
своего --query либо изменения families; иначе search_queries_not_configured
возвращается до credentials, HTTP и создания БД. Это защита от случайного
наследования чужого поиска, а не заполненный план для всех профессий.

SuperJob storage_allowed=false в стандартном TOML. Включайте его только при своих
разрешениях. Разрешения другой установки не распространяются на вашу.
Прежняя технологическая junior/middle политика сохранена как синтетическая
тестовая фикстура, не используется библиотекой или Docker по умолчанию.

Docker volume выбирается через CAREER_SCOUT_VOLUME (по умолчанию career-scout-data).
Для независимых установок выбирайте разные volume и workspace. Перед подключением
существующих данных проверьте путь; не удаляйте и не переиспользуйте чужой volume.

## Подключения вне сервера автора

Native Decisions задаётся binary/workspace/workspace_root. Стандартное имя
career-scout-decisions ищется в PATH; старый OpenBot helper и его credentials
не включены. Разрешённый каталог задавайте в своей конфигурации; серверных путей
и agent UUID в runtime нет.

Необязательный assistant_access --output требует своего существующего --output-root.
Файл создаётся эксклюзивно с0600 и принадлежит вызвавшему пользователю ОС. Фиксированного
UID, чужого агента и обязательного MCP для экспорта нет.

## Где остаются ограничения

Поддерживаются четыре конкретных источника; новый источник требует адаптера.
Хабр использует frontend JSON/HTML. Нативный Windows/macOS и модельная точность
на произвольном рынке не заявляются. Личный CLI не превращён в общий SaaS с учётными
записями пользователей. [Проверка публичной поставки](public-release.md).
