# Полный проход уже собранного массива

Ручной конечный проход обрабатывает неизменяемый снимок готовых полных вакансий,
прошедших текущие фильтры: сначала весь HH, затем Хабр, SuperJob, «Работа России».
Новые поступления коллектора не расширяют запущенный проход. База коллектора
открывается только для чтения; анализ и результаты хранятся отдельно.

Снимок содержит campaign_id, время фиксации, полные вакансии, политики фильтрации,
source_order и content_hash всего содержимого без самого content_hash. Источники
и source/id проверяются на допустимость и уникальность. Четыре резюме, инструкции,
атрибуты, модель и калибровка фиксируются отпечатком файлов конфигурации. Изменение
снимка или параметров останавливает продолжение вместо незаметной переоценки.

```sh
uv run --no-sync python -m career_scout.array_analysis --config private/analysis-applications.json --catalog data/full-array/catalog.json --freeze
uv run --no-sync python -m career_scout.array_analysis --config private/analysis-applications.json --catalog data/full-array/catalog.json --output data/full-array
```

Каждая площадка разбивается на технические порции по100карточек по умолчанию; --chunk-size400 выбирает порции400. Это размер
подготовки очереди и бюджета маршрутизации; модельный батч по-прежнему содержит
до20вакансий и одно полное резюме. На порцию приходится конечный верхний бюджет
4N модельных вызовов: до двух профилей, две попытки, с учётом возможного разделения
по размеру контекста. Это предел, а не целевое число обращений.

Decisions выбирает одного или двух оценщиков. Четыре профильные очереди работают
параллельно в единственном координаторе. При переходе к следующей порции не
запускается второй пул воркеров. Прежние admission и валидные оценки переиспользуются;
прежние незавершённые порции той же площадки продолжаются. Незавершённый старый
запуск, смешивающий площадки, останавливает проход, чтобы не нарушить порядок.

Контрольная точка state.json сохраняет run IDs до обращений к моделям. После сбоя
повторная команда продолжает эти же задачи. Если сбой случился между admission и
записью state, prepare находит прежний run по точным ключам входов. Второй
координатор с тем же output не получает блокировку. Квоты, авторизация и неизвестный
исход Decisions останавливают проход; повторов HTTP с неизвестным исходом нет.

После исчерпания допустимых попыток отдельная карточка остаётся технически
неоценённой, не превращается в REJECT. Другие порции продолжаются, а итог получает
complete_with_errors. Повторная команда не создаёт безграничные поколения попыток.
Для полного завершения всех оценок такой остаток требует отдельного технического
исправления. Вопросов владельцу и автоматических откликов нет.

В последовательном режиме после каждой порции, а в непрерывном — после фазы
площадки, остановки по лимиту или внешней ошибки — обновляется
recommended-vacancies.md: только рекомендации
по текущим резюме, с проверкой давности публикации и без повторов source/id.
Пока state.status=running, файл является промежуточной подборкой.
complete означает завершение всех задач; complete_with_errors и blocked не означают
полной оценки массива. Внутренняя категория other не выдаётся как отказ кандидату.

Тесты проверяют порядок площадок, конечность снимка, продолжение прежних pending,
отсутствие повторных admission после рестарта, остановку при внешней ошибке,
изменённые параметры, дубли identity и отличие технической ошибки от отказа.

Параметры20и Decisions screening: [evaluation-performance.md](evaluation-performance.md).

Операционные retry/budget можно изменить при остановленном координаторе с отдельной
квитанцией старой/новой конфигурации и причины. CV, правила, snapshot и selection_key
сохраняются; контрольный fingerprint обновляется явно.

## Непрерывные профильные очереди и остановка для проверки

```sh
uv run --no-sync python -m career_scout.array_analysis --config private/analysis-applications20.json --catalog data/full-array/catalog.json --output data/full-array --chunk-size 400 --continuous --stop-after 3000
```

`--continuous` использует один общий пул четырёх профильных воркеров для всех
порций текущей площадки. Пока медленный профиль работает, координатор готовит и
маршрутизирует следующие порции; свободный профиль начинает следующий батч, не
ожидая остальных. Один профиль не выполняет два батча одновременно. Батчи не
смешивают run IDs, чтобы сохранить отдельные бюджеты, попытки и происхождение.
Подготовка/Decisions и запись результатов выполняются на главном потоке; во время
подготовки следующей порции уже запущенные модельные вызовы продолжаются. Это
убирает барьер между порциями, но не гарантирует заполнение каждого батча до20.
Переход к следующей площадке происходит после завершения текущего пула.

`--stop-after N` — предел по порядковому номеру в неизменяемом каталоге, включая
уже пройденные карточки; это не N дополнительных оценок. На границе неподготовленная
порция делится, остаток остаётся в state.json. Карточки за пределом не передаются
ни маршрутизатору, ни оценщикам. Нельзя поставить предел ниже уже подготовленной
порции или разрезать её задним числом. Предел сохраняется: повторный запуск без
флага не продолжает дальше. Для разрешённого продолжения его надо явно увеличить.

Успешное достижение промежуточной границы: `status=stopped_at_limit`, exit0,
`completed_catalog_count=N`; полный каталог при этом не объявляется завершённым.
Если остались технически неоценённые карточки, статус `complete_with_errors`.
При внешней ошибке пополнение и новые модельные вызовы прекращаются, уже начатые
вызовы завершаются и сохраняются; затем `blocked`. Продолжение использует прежние
run IDs, квитанции, бюджеты и валидные оценки. Ни достижения лимита, ни продолжения
не сбрасывают количество разрешённых попыток. Блокировка БД удерживается единым
координатором и передаётся его подготовке, исключая второго писателя.

Offline-тесты проверяют начало следующей порции при занятом медленном профиле,
единственность воркера каждого профиля, барьер площадок, точное деление порции,
сохранение лимита, отсутствие повторных оценок и сохранение начатых результатов
при ошибке предварительного отбора.
