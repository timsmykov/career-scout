# Критерии приёмки

Это спецификация проверок. Фактические результаты фиксируются отдельно;
наличие сценария в списке не доказывает его прохождение.

## Сбор

C01: HH page 0/1, pages/found учтены; последний cursor после сохранения.
C02: Trudvsem offset 0/1/2, не 0/100/200.
C03: Habr page 1; список не содержит полного description — detail обязателен.
C04: SuperJob more=true, cap и пересекающиеся date windows; без потерянной границы.
C05: Дубли по source+source_id из разных запросов сохраняют discovery provenance.
C06: Другие ID с теми же company/title не исчезают.
C07: 401/403/429/quota-like503 — состояние источника, не пустая успешная выдача.
C08: Retry-After seconds и HTTP-date, finite retry и общий расход бюджета.
C09: Schema drift не создаёт full карточку с пустым описанием.
C10: Exhausted budget → partial и сохранённый backlog.
C11: В legacy collect изменённый listing делает detail stale; initial/new сохраняют старые строки и не запускают refresh.
C12: TTL refresh остаётся только в legacy collect. Initial/new не запрашивают известный full detail повторно при истечении TTL или изменении listing.
C13: 404/410 не превращается в REJECT кандидата.
C14: Сбой одного источника не затирает успешно завершённые другие.
C15: Сбой после записи страницы → безопасный повтор и resume.
C16: URL/redirect на неожиданный host/auth не загружается как description.
C17: Retention disabled не пишет текст в raw/queue/checkpoint/export.
C18: Завершение списка с deferred cards не даёт full detail coverage.

C19: Initial и new фиксируют окно14дней по публикации; start включён, на секунду старше исключён.
C20: Недавний modified_at не делает старую публикацию свежей. Без подтверждённой
даты и при недостаточной точности на нижней границе запись хранится отдельно,
но не входит в свежий экспорт, включая --include-excluded.
C21: Старые карточки и snapshots после миграции и новых проходов остаются неизменными.
C22: New экспортирует только впервые сохранённые в этой campaign описания;
известные full исключены, дочитанный backlog учтён отдельно.
C23: Resume campaign/дочернего run продолжает все четыре источника по frozen plan,
включая сохранённые окна, курсоры и недочитанные карточки.
C24: HTTP budget ограничивает chunk, а не общий объём источника; равных квот на
число карточек нет. Все доступные страницы плана должны быть пройдены до complete.
C25: Ошибка одной карточки откладывается с конечными повторами и не задерживает
остальные; failed виден, явный --retry-failed возвращает его в очередь.
C26: Известный ID не завершает поиск. Следующий ручной new может найти поздний ID
на любой странице своего14дневного окна; exact dedup не создаёт повторного detail
или второй acquisition. Старые ID, пропущенные initial по возрасту, не дочитываются
последующим daily new.

C27: Медленный Trudvsem query переобходится с меньшей страницей от0 при
неизменных запросе/датах; известные описания сохраняются. Новый query/cursor/event
пишутся атомарно, сбой возвращает прежний pending query. Уменьшение конечно,
ошибка при limit1 остаётся partial; 401/403/429 не обходятся.

C28: Явная закрытая Habr-карточка без текста/JobPosting, с совпавшими SSR ID/href
и archived=true, становится unavailable без фиктивного snapshot. Неполная
сигнатура/чужой ID/challenge остаются ошибкой. Если прежняя ошибка затем разрешена
ответом unavailable, активная очередь повторов очищается атомарно; прочие
сохранённые описания и acquisitions остаются неизменными.

C29: Плотный Trudvsem campaign query разбивается по датам с заранее закреплённой
страницей5 у детей. Все интервалы/граничные ID покрыты, старый cursor и full rows
сохранены, известные описания не скачиваются вновь. Total>300 — цель размера
окна, не cap: при интервале1сек собираются все записи, даже если их больше цели.
Оценка публикации использует исходные14дней. Split/child pins откатываются вместе
при DB-сбое; возобновление не меняет frozen plan.

## Фильтры

F01: Явные senior/lead/head роли и 4+ mandatory исключаются.
F02: 1–3, no experience, junior/middle проходят.
F03: Unknown/конфликт категории и текста остаётся на рассмотрение.
F04: Senior-коллега/будущий руководитель не повышает grade вакансии.
F05: Технологический assistant и automation в нетехнологической компании возможны.
F06: Отсутствие зарплаты не исключает; 120 net не внедрён как global cutoff.
F07: Новый фильтр пересматривает затронутые старые исключения.

## Оценка и состояние — реализация и отдельная приёмка

E01: Полный текст выбранного резюме передан, другие резюме/чужие решения отсутствуют.
E02: PASS в позиции 1 вызывает ровно одного оценщика; позиции 2/3/4 аналогично.
E03: После раннего BORDERLINE/ERROR поздний PASS принимает вакансию.
E04: Общий REJECT только из четырёх валидных REJECT.
E05: Нет PASS, есть ERROR → PENDING; без ERROR, есть BORDERLINE → NEEDS_CLARIFICATION.
E06: Сломанный JSON/невалидная схема/несуществующая цитата → error, не отказ.
E07: Содержательно отсутствующий навык → unconfirmed; явный несовместимый → conflict.
E08: Желательное требование не становится hard reject.
E09: Вакансия с prompt injection не меняет правила/действия/источники.
E10: Изменение resume/content/filter/rubric/model/evaluator инвалидирует нужный key.
E11: Изменение order создаёт новый route; сохранённые отдельные оценки совместимы
только по своим ключам и потребляются в новом порядке до первого PASS.
E12: Сбой после LLM ответа до ledger commit может повторить оплату, но не создаёт
два канонических результата. Это документируется, а не называется exactly-once.
E13: Единственный исполнитель через flock; повторное открытие БД и checkpoints
не теряет проверенные результаты. Распределённые leases в текущий этап не входят.
E14: Отсутствие подтверждённого model ID/порядка/резюме предотвращает evaluate.
E15: Превышение контекста не вызывает silent truncation.
E16: У skipped профилей нет выдуманного REJECT.
E17: Native ChatGPT login, отсутствие ключей API и инструментов в worker;
ошибки auth/model/schema/quota останавливают batch с PENDING.
E18: Короткие ссылки восстанавливают только непрерывный диапазон исходного
текста; неверный источник/порядок/длина дают ERROR. Полные тексты не сокращаются.
E19: Ledger и LangGraph checkpointer используют разные SQLite connections;
фоновые checkpoints не коммитят транзакции журнала попыток.
E20: Бюджет резервируется до вызова и сохраняется после сбоя; только явное
продолжение увеличивает бюджет или начинает новое поколение попыток.

Offline evidence: tests/test_analysis.py. Реальные пилоты проверяют транспорт и
примеры решений; оценка качества требует отдельно размеченной выборки. Защита
от prompt injection ограничивает инструменты и проверяет выход; её семантическая
устойчивость также проверяется на контрольных примерах, а не гарантируется схемой.

## Пригодность для владельца

Для текущего collector MVP проверять C/F-сценарии, качество данных и передачу набора.
E-сценарии и метрики модельных вердиктов принимаются независимо от коллектора.

На отдельной ручной разметке измерить потери подходящих вакансий на каждом этапе,
ложные принятия, долю вопросов, долю технических ошибок, охват плана и затраты.
Не использовать один итоговый accuracy на несбалансированных данных.
Не объявлять широкий рынок охваченным по абсолютному числу карточек.

Bootstrap acceptance: checker проходит, env install воспроизводим по lock,
package import/build проходит, Git не содержит private/.env/runtime data,
GitHub readback совпадает с локальными документами.
