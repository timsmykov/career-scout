# Фильтры

Подтверждённые правила владельца: технологическая работа ИЛИ технологическая
сфера компании; стажёр/junior/middle; без опыта/1–3 года.

## Таблица

| Признак | Действие |
|---|---|
| Явный grade senior/lead/head именно вакансии | FILTERED_OUT |
| API category 3–6 или более 6 лет | FILTERED_OUT |
| Явный обязательный минимум 4+ года | FILTERED_OUT |
| Явно 3 года | Пропуск к оценке фактического резюме |
| Нет опыта/грейда/сферы | KEEP_UNKNOWN |
| Категория и полный текст противоречат | KEEP_UNKNOWN с conflict |
| Слово senior описывает коллегу | Не использовать как grade вакансии |
| Нет слова AI, но технологическая функция | Пропуск |
| Зарплата не указана | Пропуск |
| Требование желательно | Само по себе не причина отказа |

## До LLM

Код применяет структурированные доказуемые ограничения.
Не распознавать роль сложным regex по всему тексту, если контекст неоднозначен.
Unknown сохраняется для предметного оценщика. Отсутствие нужного ключевого слова
не доказывает нетехнологическую работу.

Явный senior в названии с отрицанием/смешанными уровнями — conflict, не механический
substring reject. Границы слов и поле происхождения обязательны.
Если сфера неоднозначна, полный текст читает воркер; «кодовый этап» не требует
решать все смысловые случаи до LLM.

## Изменение атрибутов

У каждого набора filter_version, owner, changed_at, values.
География/формат/оформление/доход null = нет ограничения, не wildcard-догадка.
В examples не внесён глобальный минимум 120 net.

Любое изменение фильтра создаёт новую версию. Повторно рассмотреть сохранённые
исключения, которых касается изменение, не полагаться на устаревший отказ.
