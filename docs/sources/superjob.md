# SuperJob

Runtime реализован в adapters.py/source_normalization.py; [общий запуск и точный статус](../multi-source.md).


Официальные страницы:
https://api.superjob.ru/
https://api.superjob.ru/rules/
https://api.superjob.ru/doc/

Поиск: GET https://api.superjob.ru/2.0/vacancies/
Заголовок X-Api-App-Id: собственный ключ приложения из secret store.
Параметры keyword, page (0), count; objects/total/more проверяются по reference.
Поля текста: vacancyRichText либо обязанности/требования/условия.
Не сохранять только title/company/salary: это недостаточный input модели.

В доступной legacy справке: 120 запросов/мин/IP, до 500 сущностей в выдаче.
Это документированные значения legacy, не подтверждённые лимиты нашего ещё
неполученного доступа. 503 может означать превышение квоты.
Фактический count/page_size проверяется; данные автора radar про ~40/page не гарантия.
При поддержке date_published_from/to большие выборки разбивать по датам.

Состояние 11.11.2026: приложение Career Scout создано, ID 5273.
Сайт заявки — публичный профиль разработчика GitHub, Callback пустой.
Собственный ключ приложения проверен: search и detail HTTP 200,
ID detail совпадает со списком, текст описания получен. Пользовательский OAuth
для этого ограниченного чтения не использовался. /doc/ ранее недоступен (403).
Ключ хранится только в локальном .env, его значение не включено в Git.

11.11.2026 владелец прямо подтвердил наличие всех разрешений на хранение вакансий.
По этому подтверждению runtime использует enabled=true, storage_allowed=true:
полные вакансии, версии, discoveries и результаты фильтров сохраняются в общей SQLite.
Прежний статус ожидания подтверждения снят. Исторические отчёты с disabled сохранены
как результаты предыдущего состояния; новые доказательства —
[superjob-storage-live-20261111.json](../references/superjob-storage-live-20261111.json).

Отдельная конфигурация со storage_allowed=false по-прежнему блокирует запись;
probe читает в памяти. Старые frozen планы не переписываются. Модели/агенты
не подключаются этим изменением. Подтверждение разрешений получено от владельца,
отдельных новых согласований с площадкой агент не проводил.

Создание приложения с адресом профиля подтверждено самим владельцем;
это не общее правило приёма любых GitHub-профилей в будущих заявках.
