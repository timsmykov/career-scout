# Работа России / Trudvsem

Runtime реализован в adapters.py/source_normalization.py; [общий запуск и точный статус](../multi-source.md).


Официальный контракт:
https://opendata.trudvsem.ru/api/v1/vacancies/application.wadl
https://trudvsem.ru/opendata/api

REST base: https://opendata.trudvsem.ru/api/v1/vacancies
Search GET с text/limit/offset и поддерживаемыми WADL фильтрами.
offset здесь номер страницы: 0,1,2; не количество пропущенных строк.
В предыдущем чтении WADL default limit=100; не выдавать за гарантию всех максимумов.
Detail и состав identity проверить по WADL: companycode и id могут нужны совместно.

Полный смысл складывается из duty, requirement.qualification, employment/schedule
и прочих условий. Пустая qualification не означает, что duty неполный, но отсутствие
ключевого текстового содержания — missing. Оценку полноты определять контрактом,
не произвольной длиной строки.

HTTP 200 не достаточен: проверять body status, results, meta и критичные типы.
Пустая results может приходить без vacancies. Сохранять source ID, точность даты,
отдельно creation/date_modify/fetched.

Проверены search/detail HTTP 200 в предыдущем ограниченном прогоне 11.11.2026.
Универсальная квота запросов не подтверждена; interval=1s — проектная политика.
Если выдача усечена, разделять запрос только поддерживаемыми фильтрами и фиксировать
остаток. XSD массовой XML выгрузки не подменяет контракт REST.

По реальной проверке 12.11.2026 глубокая страница29 с limit20 не ответила
даже за90сек; совпадающая часть выдачи с limit10 ответила за8,8сек.
В campaign режиме transport/5xx запускает сохранённый replan того же запроса
с меньшей страницей и обходом от0:20→10→5→2→1. Это настройка клиента,
не утверждение об официальном максимуме API. Повторный detail известных ID
не выполняется; ошибка на минимальной странице остаётся явно partial.

Плотные campaign-запросы с известным total>300 делятся по modifiedFrom/modifiedTo.
300 — рабочая цель размера подокна, не лимит API и не предел числа вакансий.
Дочерние окна покрывают родителя с общей включённой границей, получают cursor0
и заранее закреплённую страницу5. Записанный префикс родителя сохраняется;
известный total позволяет разделить возобновлённый запрос без его перечитывания.
Окно в1сек больше не делится: вся выдача дочитывается нативными страницами.
Публикация проверяется по исходным14дням campaign, не по дочернему окну изменения.
Live-пробы12.11: сутки со страницей5 дали91/111карточек; точные равные
modifiedFrom/To вернули карточку на границе. Страницы20 в тех же узких диапазонах
давали ReadTimeout; это наблюдаемое поведение, не гарантия времени ответа API.
[Live-проверка](../references/trud-window-partitions-live-20261112.json) фиксирует
дочерние окна, сохранность3595снимков и покрытие исходного плана; общий initial
в момент проверки ещё partial.
