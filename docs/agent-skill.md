# Подключить своего агента

В пакет входит один переносимый Agent Skill `career-scout`: он охватывает настройку,
сбор и анализ на российских площадках. Международный поиск пока вне охвата
инструмента: для него нужны другие источники и отдельный механизм.
Условные инструкции разделены на два references-файла, которые агент
читает по задаче. Отдельный навык для каждой профессии не нужен.

После установки самого CLI:

```sh
career-scout skill install --agent codex
# Или для Claude Code:
career-scout skill install --agent claude
```

Codex получает папку в `$CODEX_HOME/skills` или `~/.codex/skills`, Claude Code — в
`~/.claude/skills`. Чтобы установить в project-local/custom каталог навыков:

```sh
career-scout skill install --agent codex --directory /path/to/project/.agents/skills
```

Команда возвращает JSON с фактическим путём. Повторная установка той же версии
ничего не меняет; отличающаяся папка или symlink дают `skill_destination_conflict`.
Сначала сохраните свои изменения и вручную выберите каталог для обновления.
Никакие конфиги агента, токены и рабочие базы установка не меняет. Команды
`skill install/show` не требуют workspace/request-id: установка идемпотентна по
содержимому и не создаёт control DB.

Перезапустите обнаружение навыков/сессию агента. Пример поручения:

> Используй $career-scout. Вот мои полные резюме и пожелания. Настрой отдельный
> workspace, покажи поисковый план и выполни первую пробу в пределах200HTTP и
> 4модельных вызовов. Верни подходящие вакансии со ссылками. Не отправляй отклики.

Установка навыка не выполняет это поручение автоматически. Агент использует
собственный разрешённый способ запуска shell/процессов. Для других совместимых
агентов скопируйте папку [career-scout](../src/career_scout/skills/career-scout/SKILL.md)
в их каталог Agent Skills. `career-scout skill show` возвращает entrypoint в JSON.
Никаких зависимостей от личного OpenBot, аккаунта автора или фиксированных профессий.

Агент сначала читает `version`, `schema`, `provider list`; создаёт контекст,
план и подключение из схем; проверяет `plan preview` и `doctor --context`; сохраняет
возвращённые IDs и квитанции; выполняет сбор/оценку с конечными бюджетами. Он
различает command success и complete run, читает все страницы, продолжает прежние
запуски и не обходит блокировку неизвестной доставки. Результат — подборка PASS.

Настройка API/подписок: [model-providers.md](model-providers.md). Полный контракт:
[agent-cli.md](agent-cli.md). Резюме, параметры, источники и подключения каждый
пользователь задаёт свои; сам скилл и установка не предоставляют ключей площадок
или моделей. Подписочные CLI ставятся и авторизуются отдельно.
